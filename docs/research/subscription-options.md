# Claude subscription execution options

2026-10-28. Public-document research and offline inspection of Agent SDK 0.3.312 / Claude Code 2.1.312. No authenticated Anthropic requests, credential reads, live sessions, or subagents. The only inference probes used dummy authentication against loopback.

## Ranked recommendation

**1. Anthropic-hosted cloud sessions, driven through the official CLI, remote HTTP MCP, and HTTP hooks.** This removes local execution processes during cloud work without operating containers. Keep this as a distinct backend: Claude Code owns its agent loop and canonical conversation. The DO retains orchestration, workspace tools, action scheduling, and received events. If the actual loop and authoritative transcript must remain entirely in the DO, this option fails that requirement; no verified subscription mechanism meets every constraint.

**2. Keep demand-spawned, concurrency-limited local SDK turns as the conservative subscription backend.** They preserve the proposed tool boundary and release processes after turns. Queueing 100 threads behind eight slots needs eight execution processes, but delivers eight simultaneous turns, not 100. Fix transcript durability before calling the DO authoritative.

**3. Offer subscription-funded API credits as the compute-efficient alternative.** This preserves pi-durable completely, but spends a separate finite credit balance rather than Pro/Max subscription limits.

## Compliance boundary

[Support 15036540][support] confirms: “For now, nothing has changed: Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription limits.” It displays “Updated yesterday,” consistent with October 27. Its October 7 update confirms Max/Team API credits.

Billing eligibility is not blanket integration permission. The [SDK overview][overview] still says: “Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK.”

The [legal page][legal] supplies the narrower hosting exception: “Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code as described under Can customers offer Claude Code in their products? above.” Hosting requires Commercial Terms, an unmodified binary, all built-in authentication choices, individual authentication, and direct billing. Treat personal automation and a distributed subscription-login product separately.

## Cloud path details

Create through `claude --cloud "task"` or claude.ai/code. Then use `claude -p "follow-up" --cloud <id> --output-format json`. The [docs][cloud] explicitly permit CI follow-ups: “The CLI queues the message into the session and exits without waiting for a reply.” JSON acknowledges dispatch, not completion; stream-json is unsupported. New-session `--cloud "description"` cannot combine with `-p`, so fully unattended hosted creation remains a gap.

[Cloud environment docs][environments] explicitly carry repository `.mcp.json` into single-repository sessions outside Projects. Configure remote HTTP MCP for DO tools, plus [HTTP hooks][hooks] for `PostToolUse`, `Stop`, and `StopFailure`; Stop supplies `last_assistant_message`. This observes tool/turn boundaries, not a guaranteed full token/transcript stream. Cloud Projects instead use claude.ai connectors. Configure network access for the endpoints. Git-only cloud work is also valid; it changes the DO workspace handoff.

[Authentication][auth]: “This token authenticates with your Claude subscription and requires a Pro, Max, Team, or Enterprise plan. It can only make model requests, so it can’t establish Remote Control sessions or fetch claude.ai connectors.” That is `setup-token`: official for headless model requests, not cloud control. [CI docs][testing] explicitly require `user:sessions:claude_code`, cap its refresh grant at 30 days, and state no long-lived cloud-control CI token exists today. Keep authentication inside the user's CLI.

## Multiplexing, exports, and measurements

Self-hosted runners share queue management, not agent runtimes. [Reference][reference]: `--capacity` defaults to one; runners lock to one owner. Enable `--release-idle-session-min` because zero disables release; `--exit-if-unused-min` handles never-used runners. Autoscaling shares hosts over time, but adds infrastructure.

`/bridge` exports alpha transport/credential/session helpers; it is not the self-hosted runner or an inference engine. Its create helper creates a bridge session, not an Anthropic execution VM. Embedded subprocess libraries do not establish a runner implementation. Offline 2.1.312 inspection confirms Remote Control's spawner invokes `child_process.spawn` with `--print --sdk-url`; the documented “single process” server is not evidence of shared session memory.

`/browser` has public `.d.ts` examples and [CHANGELOG][changelog] entries 0.3.169, 0.3.267, 0.3.304, and 0.3.307. Types require caller-supplied Authorization/platform headers; they provide no login or refresh flow. However, searches of the official docs index and TypeScript reference found no browser attachment/authentication guide. Exported protocol support does not establish third-party authorization. Existing workerd/MCP results remain fake-server evidence.

Offline Mac arm64 probe: eight seconds each, dummy API key, loopback hanging HTTP server, clean allowlisted environment, read-only HOME/config, credential-helper PATH unavailable, tools/settings discovery/persistence disabled. Both reached only local `/v1/messages?beta=true` and exited on SIGTERM. RSS, KiB: normal final/peak **184368/184368**; bare **154416/173808**. One sample each, no inference/context growth; summed RSS is not physical-memory accounting. [Bare docs][headless]: “In bare mode, Claude Code never reads OAuth credentials or the system keychain.” Bare therefore cannot optimize subscription turns. `/core` reduces wrapper loading; prewarm reserves memory and can be claimed once, not multiplexed.

Finally, [SessionStore][storage] writes locally first and mirrors best-effort; failed batches can be dropped while execution continues. `tools: []` does not mean no local transcript. The [Pi rejection][pi] is corroborated as a reported October 18 failure, not rerun. [Managed Agents][managed] supplies official hosted APIs/custom tools, but uses API credits/billing and moves the loop out of the DO too.
